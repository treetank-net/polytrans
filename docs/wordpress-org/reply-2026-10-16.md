Hello,

Thank you for the review. Version 1.24.2 is uploaded and addresses every point. Because
you noted that the examples are not exhaustive, we fixed each pattern everywhere it
occurs, not only on the lines you quoted, and added CI checks so these issues cannot
return unnoticed.

**Activation on a fresh install with WP_DEBUG**
The undefined `logs_retention_days` key is fixed. Every release now goes through an
automated version of your manual test, on the current WordPress release and on our
declared minimums (WordPress 6.0, PHP 8.1). The test uses a fresh install with `WP_DEBUG`
and `WP_DEBUG_LOG`, activates the plugin from the Plugins screen as an administrator, and
opens the dashboard, the post editor and every plugin screen. It fails on any PHP
warning, notice or deprecation, on output during activation, on a missing table, on our
assets loading outside our screens, and on any external HTTP request made without
configuration.

**cURL**
`BackgroundProcessor` now uses only `wp_remote_post()`. The cURL and
`file_get_contents()` fallbacks are removed.

**`$_COOKIE`**
The async worker no longer receives cookies at all. It is authenticated by a per-job
HMAC token, and no job reads the current user. The plugin no longer reads `$_COOKIE`
anywhere.

**Escaping output**
Every template is printed through `wp_kses()` with an explicit allow-list at the point
of `echo`. Previously the code echoed already-rendered markup. This covers all ~21 call
sites, not only the 12 you listed. The workflow meta box CSS has moved from
`wp_add_inline_style()` to an enqueued stylesheet.

**Direct calls to AI providers / WordPress AI Client**
We looked at the AI Client in WordPress 7.0 closely. The plugin keeps its direct
integrations for now, for reasons that affect translation quality rather than
convenience:

- Current OpenAI models (GPT-5.x) are used through the Responses API, with a configurable
  reasoning effort. The AI Client exposes neither.
- Translating a long article with high reasoning effort takes minutes. The plugin runs
  these calls as background jobs. The AI Client's 30-second default request timeout is
  shorter than many of them.
- The plugin records token usage per call to report translation costs per post and per
  language. That needs the provider's full usage block.
- The compatibility package for WordPress < 7.0 (`wordpress/wp-ai-client`) is
  deprecated, and the plugin supports WordPress 6.0+.

All provider requests go through the WordPress HTTP API. They are made only after an
administrator enters an API key. The only other request, an anonymous read of a public
price list from openrouter.ai used for cost estimates, carries no key or content. All of
them are disclosed in the readme's "External services" section. We plan to add the WordPress AI Client as an additional, optional provider in a
later release, for sites that configure AI centrally in WordPress 7.0+. Our developer
documentation, which quoted the provider endpoints, is no longer part of the
distribution.
